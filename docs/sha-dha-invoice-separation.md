# SHA ILM Invoice Separation (DHA vs Local)

## Why this change was made

We identified two different invoice domains being treated as one:

- **Local billing invoice**: generated by Vitora (format like `INV-YYYYMMDD-XXXX`)
- **DHA ILM invoice**: returned by DHA preview/lifecycle APIs (format like `INV/13545/73342`)

Using local invoice numbers in DHA lifecycle submit/discharge flows caused mismatches and unreliable submissions.

## What changed

### 1) Explicit DHA invoice field on SHA claims

A dedicated field was added to store the DHA invoice number:

- Model field: `SHAClaim.dha_invoice_number`
- Migration: `backend/hmis/apps/billing/migrations/0061_shaclaim_dha_invoice_number.py`

This keeps DHA invoice identity separate from local `claim.invoice` / `invoice_number`.

### 2) Preview/apply now persist DHA invoice

In `SHAClaimViewSet` ILM endpoints:

- `ilm_preview` extracts invoice from payload and stores to `claim.dha_invoice_number`
- `ilm_apply_preview_lines` stores detected DHA invoice to `claim.dha_invoice_number`
- `ilm_apply_preview_lines` **no longer attempts to link local invoice** by string-matching DHA invoice number

Extraction supports `invoice_number`, `invoice_no`, or `invoice` keys inside `payload.invoices[]`.

### 3) Submit uses DHA invoice semantics

`ilm_submit` now uses:

1. `request.data.invoice_number` (if explicitly provided), else
2. `claim.dha_invoice_number`

If neither exists, API returns a clear error asking the user to run preview first.

### 4) Serializer and frontend shape updates

Claim responses now expose both invoice identities:

- `invoice_number` -> local invoice (from `invoice.invoice_number`)
- `dha_invoice_number` -> DHA invoice used for ILM lifecycle

Updated in:

- `backend/hmis/apps/billing/sha_serializers.py`
- `web-app/lib/types/sha.ts`
- `web-app/lib/schemas/sha.schema.ts`

### 5) Workflow UI now shows both invoices

`ClaimILMPanel` and workflow wiring were updated to:

- display both **DHA invoice** and **Local invoice** side-by-side
- use DHA invoice for outpatient ILM submit
- continue showing local invoice for local billing context only

### 6) Outpatient auto-created claim no longer auto-links local invoice

In outpatient claim auto-creation (`_maybe_create_phc_claim`), claims are now created with:

- `invoice=None`

This prevents coupling claim lifecycle correctness to local invoice creation/linkage at claim-creation time.

## Operational behavior after this change

- Running ILM preview sets/refreshes `dha_invoice_number`.
- Applying preview lines updates claim items and persists DHA invoice.
- Submission/discharge ILM operations should use DHA invoice identity.
- Local invoice linkage remains optional and independent.

## Known implications

- Existing claims created before this change may not have `dha_invoice_number` populated until preview is run.
- Local validation still checks for required attachments and tariff mapping. Missing local tariffs will still block submit.

## Rollout steps

1. Run migration:

```bash
python backend/manage.py migrate
```

2. For in-flight claims with blank DHA invoice:

- Run **Preview claim** once in workflow UI.
- Re-attempt submit.
